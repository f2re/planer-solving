# Офлайн-установка и обновление Planner Solving

## Общая схема

Полностью отключённая машина не может скачать обновление самостоятельно. Обновление готовится на машине с интернетом, переносится на USB-носителе или через разрешённый файловый шлюз и устанавливается локально.

Офлайн-пакет содержит:

- исходный код конкретной версии;
- все рабочие Python-зависимости в `wheelhouse`;
- манифест версии, Python, платформы и архитектуры;
- SHA-256 каждого файла;
- установщик, обновление и откат;
- миграции данных и локальную проверку работоспособности.

Рабочие данные, преподаватели, шаблоны и сформированные расписания в пакет не включаются.

## Требования к целевой машине

- Linux x86_64 или другая архитектура, совпадающая со сборочной машиной;
- Python той же основной и дополнительной версии, что указана в пакете, сейчас рекомендуется Python 3.11;
- модуль `venv` для этого Python;
- `bash`, `tar` и стандартные системные утилиты;
- systemd — только для установки как службы.

Для Astra Linux и других закрытых систем пакет рекомендуется собирать на машине с такой же версией ОС либо на самой старой совместимой системе. Это снижает риск несовместимости glibc у бинарных Python-колёс.

## Получение пакета на машине с интернетом

### Вариант 1 — локальная сборка

```bash
cd planer-solving
git checkout main
git pull
python3.11 -m pip install --upgrade pip
bash offline/build_offline_bundle.sh --output dist
```

Будут созданы файлы:

```text
dist/planner-solving-offline-<версия>-linux-<архитектура>-py311.tar.gz
dist/planner-solving-offline-<версия>-linux-<архитектура>-py311.tar.gz.sha256
```

Проверка:

```bash
cd dist
sha256sum -c *.tar.gz.sha256
```

### Вариант 2 — GitHub Actions

В разделе **Actions → Offline bundle → Run workflow** запускается сборка Linux x86_64 / Python 3.11. После завершения скачивается артефакт `planner-solving-offline-linux-x86_64-py311`.

Этот пакет является универсальной сборкой Ubuntu 22.04. Для Astra Linux надёжнее выполнить локальную сборку на совместимой машине.

## Перенос на закрытый контур

На носитель копируются оба файла: архив и `.sha256`. На целевой машине:

```bash
sha256sum -c planner-solving-offline-*.tar.gz.sha256
tar -xzf planner-solving-offline-*.tar.gz
cd planner-solving-offline-*
python3 verify_bundle.py .
```

Контрольную сумму желательно передавать по отдельному доверенному каналу.

## Первая установка

```bash
sudo bash install_or_update.sh \
  --install-dir /opt/planner-solving \
  --service-user planner \
  --port 8001
```

Если существует прежняя установка из Git-репозитория:

```bash
sudo bash install_or_update.sh \
  --install-dir /opt/planner-solving \
  --legacy-dir /home/user/planer-solving \
  --service-user user \
  --port 8001
```

Из старой установки переносятся:

- `data/workspaces.json`;
- `teachers.json`;
- `config.json`;
- существующие файлы из `output`.

Исходный каталог не удаляется и остаётся дополнительной резервной копией.

## Последующие обновления

Новый пакет распаковывается в отдельный временный каталог, затем выполняется та же команда без `--legacy-dir`:

```bash
sudo bash install_or_update.sh \
  --install-dir /opt/planner-solving \
  --service-user planner \
  --port 8001 \
  --yes
```

Установщик выполняет следующие действия:

1. проверяет контрольные суммы пакета;
2. проверяет версию Python и архитектуру;
3. создаёт новый неизменяемый выпуск в `releases`;
4. устанавливает зависимости только из локального `wheelhouse`;
5. останавливает службу;
6. создаёт резервную копию общих данных;
7. запускает миграции;
8. проверяет импорт приложения и целостность данных;
9. атомарно переключает ссылку `current`;
10. запускает службу и опрашивает `/api/health`;
11. при любой ошибке автоматически возвращает прежний выпуск и данные.

## Структура установленной системы

```text
/opt/planner-solving/
  current -> releases/2.3.0-20260801-120000
  releases/
    2.2.0-...
    2.3.0-...
  shared/
    data/workspaces.json
    teachers.json
    config.json
    input/
    output/
    backups/
  state/
    run.sh
    last-update.json
    history.jsonl
```

Код выпуска не изменяется. Все рабочие данные находятся в `shared`, поэтому переключение версии не заменяет их.

## Откат

Откат возвращает предыдущий код и резервную копию данных, созданную непосредственно перед обновлением:

```bash
sudo bash rollback.sh \
  --install-dir /opt/planner-solving \
  --port 8001
```

Перед откатом автоматически создаётся ещё одна аварийная копия текущих данных. Если сам откат завершится ошибкой, установщик вернёт состояние до попытки отката.

Важно: откат данных удаляет изменения, внесённые пользователями после обновления. Аварийная копия сохраняется в `shared/backups`.

## Работа без systemd

```bash
bash install_or_update.sh \
  --install-dir "$HOME/planner-solving" \
  --no-systemd

"$HOME/planner-solving/state/run.sh"
```

В этом режиме установщик проверяет импорт и данные, но не выполняет HTTP-проверку запущенной службы автоматически.

## Проверка установленной системы

```bash
cd /opt/planner-solving/current
sudo -u planner .venv/bin/python -m tools.healthcheck \
  --app-root . \
  --data-dir /opt/planner-solving/shared/data

curl http://127.0.0.1:8001/api/health
```

## Резервное копирование

Для ежедневной резервной копии достаточно сохранять каталог:

```text
/opt/planner-solving/shared
```

Минимально обязательны:

- `shared/data/workspaces.json`;
- `shared/teachers.json`;
- `shared/config.json`.

Каталог `output` можно хранить по собственной политике срока хранения.

## Ограничения

- Пакет с бинарными колёсами нельзя без проверки переносить между разными архитектурами и версиями Python.
- Сборка GitHub Actions не гарантирует совместимость с любой версией Astra Linux.
- Откат к версии, не понимающей текущую схему данных, возможен только вместе с резервной копией данных.
- Установщик рассчитан на один активный процесс приложения во время миграции и сам останавливает известные службы.

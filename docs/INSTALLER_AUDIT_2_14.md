# Аудит автономного установщика 2.13 и исправления 2.14

## Выявленные причины отказа

1. Пакет содержал wheelhouse, но не содержал Python требуемой версии.
2. Системный Python Astra 3.7 не мог установить пакет `py312`.
3. Поиск выполнялся преимущественно для пользователя службы, а не для
   пользователя, вызвавшего `sudo`.
4. `--python` принимал только точный исполняемый файл и пытался запускать
   переданный каталог.
5. Корень pyenv, `bin`, shim, каталог версии и stdlib не нормализовались.
6. Pyenv-Python с существующим, но не зарегистрированным `libpython` считался
   полностью нерабочим.
7. Venv из домашнего каталога нельзя безопасно использовать напрямую из
   systemd с `ProtectHome`.
8. Обновление не показывало полный перечень проверенных Python/venv.
9. Проверка пакета зависела от наличия достаточно нового Python на цели.
10. Не было проверки повторной установки собранного архива с сохранением
    данных.

## Архитектура 2.14

- пакет `-runtime` включает CPython;
- shell-проверка архива не требует Python;
- поиск охватывает текущие и предыдущие venv, runtime, pyenv, asdf, conda,
  системные и пользовательские пути;
- путь `libpython` восстанавливается локально через `LD_LIBRARY_PATH`;
- выбранный Python экспортируется в `/opt/planner-solving/runtime`;
- каждый выпуск получает новый venv;
- systemd использует только `/opt`;
- установка блокируется lock-файлом;
- до переключения выполняется preflight от имени пользователя службы;
- после остановки службы проверяется порт и создаётся резервная копия;
- откат восстанавливает данные, symlink, unit, EnvironmentFile и активные
  службы;
- `planner-solving-python` показывает все кандидаты и причины отказа;
- CI устанавливает и повторно обновляет готовый архив, проверяя сохранность
  маркерных данных.

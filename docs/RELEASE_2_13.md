# Выпуск 2.13 — восстановление запуска интерфейса и службы

## Исправлено зависание до загрузки окна

Причина находилась в `ui-runtime-fixes.js`: `MutationObserver` следил за `minlength`, обработчик удалял атрибут и тут же создавал его снова через свойство DOM. Браузер бесконечно выполнял микрозадачи ещё до `Vue.mount()`.

В 2.13 обработчик стал идемпотентным, основной интерфейс монтируется раньше необязательной политики формы, а отдельная проверка воспроизводит очередь мутаций и подтверждает её остановку.

## Усилен запуск браузерной части

- защита от повторного запуска приложения;
- десятисекундный сторож запуска;
- видимое окно с текстом исключения вместо пустой страницы;
- обработка `error` и `unhandledrejection` до монтирования;
- HTML отдаётся без кэша;
- JavaScript и CSS обязательно перепроверяются после обновления.

## Переработана установка

Штатный корень — `/opt/planner-solving`.

Каждый выпуск получает собственный `.venv`, который создаётся до переключения `current`. Все зависимости устанавливаются только из автономного `wheelhouse`. Затем системный пользователь службы запускает предварительную проверку импортов. Выпуск не активируется, если пользователь `planner-solving` не видит Python или хотя бы одну библиотеку.

## Переработан systemd

Служба больше не зависит от `PATH`, `pyenv`, `.bashrc` и пользовательских библиотек. Unit вызывает стабильный сценарий:

```text
/opt/planner-solving/state/run-service.sh
```

Он выбирает:

```text
/opt/planner-solving/current/.venv/bin/python
```

и выполняет полную проверку до Uvicorn.

## Диагностика

Добавлена команда:

```bash
sudo planner-solving-doctor
```

Она проверяет структуру установки, venv, импорты, права, systemd, журнал, порт, HTTP и сведения последнего обновления.

## Автономный пакет

Пакет содержит:

- приложение;
- все Python-колёса;
- внутренний manifest и контрольные суммы;
- стабильный запускатель;
- диагностический сценарий;
- автоматический откат;
- краткую инструкцию `README-INSTALL.txt`.

CI теперь выполняет не только сборку архива, но и полную тестовую установку из него, создание venv, миграции и `run-service.sh --check`. Для основной ветки готовый пакет публикуется как артефакт GitHub Actions.

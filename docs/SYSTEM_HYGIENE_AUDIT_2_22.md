# Planner Solving 2.22 — аудит чистоты репозитория и автономного пакета

## Методика

Очистка выполнена по графу фактической достижимости, а не по названию файла. Для каждого кандидата проверялись:

1. входящие Python-импорты, ES-модули, HTML-ссылки, CSS `url()` и строки загрузчика;
2. использование установщиком, systemd, миграциями, документацией и тестами;
3. наличие файла в автономном архиве и установленном выпуске;
4. полный тестовый контур после удаления.

Публичные вспомогательные функции и эксплуатационные документы не удалялись только на основании отсутствия внутренних вызовов: они сохранены как совместимый API и операторская документация.

## Удалено из репозитория

- `inspect_bottom.py`, `inspect_xlsx.py` — одноразовые диагностические скрипты;
- `main.py`, `run_full_process.py` — старые CLI, завязанные на отсутствующую структуру `obrazec`;
- `teacher_schedules.xlsx` — сгенерированный результат;
- `plan.md` — ранний план с уже заменённой архитектурой;
- `planner-web.service` — старый unit, не используемый установщиком;
- `bootstrap.min.css`, `readability.css` — неподключаемые таблицы стилей;
- `.gemini/agents/frontend_developer.toml` — дублирующий агент с несовместимым React/Tailwind/CDN-стеком.

Файл `clean-flow-2-21.css` переименован в нейтральный `interface-clean.css`: это действующий слой интерфейса, а не версия-времянка.

## Стили и JavaScript

Весь каталог frontend проверяется как граф достижимости. Активные CSS-файлы и динамические классы не удалялись только потому, что селектор не встречается буквальной строкой в HTML: Vue-классы, severity-состояния и расширения могут формироваться программно. Это защищает интерфейс от агрессивной ложной очистки.

Удалены две полностью неподключаемые таблицы стилей. Из `ui-runtime-fixes.js` удалён невызванный `applyEditorRuntimeFixes`, дублировавший актуальную реализацию редактора. Политика полей пароля сохранена.

В `service_preflight` добавлена проверка полного графа статических ресурсов. Служба теперь обнаруживает:

- отсутствующий JS/CSS/изображение/manifest;
- импорт за пределами каталога frontend;
- пустой ресурс;
- любой файл frontend, который не достижим из entrypoint, импорта, CSS или manifest.

## Зависимости

Из runtime исключены `ortools`, `pandas` и `python-dateutil`. Рабочий код их не импортировал; `pandas` использовался только удалёнными диагностическими скриптами. Вместе с ними из wheelhouse уходят NumPy, protobuf, absl-py, immutabledict и six.

Runtime сохраняет только:

- `openpyxl`;
- `fastapi`;
- `uvicorn`;
- `python-multipart`;
- `pydantic`;
- их необходимые транзитивные зависимости.

Сборщик отдельно запрещает возврат тяжёлых неиспользуемых wheel-пакетов.

## Автономный пакет

В установленное приложение больше не копируются:

- каталог `offline/` — его необходимые скрипты уже находятся на верхнем уровне пакета;
- `.gitignore`, `GEMINI.md`, dev-зависимости и тесты;
- исторические аудиты и release notes;
- удалённые debug/generated-файлы.

Сохраняются шесть эксплуатационных документов: установка, обновление, руководство оператора, сброс пароля, runtime README и диагностика.

Локальная контрольная сборка без Python runtime сократила:

- приложение: с 2,4 до 1,7 МБ;
- wheelhouse: с 60 до 3,5 МБ;
- число wheel-файлов: с 24 до 16;
- число файлов приложения: со 172 до 122.

Финальный размер архива с Python runtime фиксируется CI, поскольку runtime остаётся неизменным и является основной частью пакета.

## Защита от ошибочного удаления

Добавлены регрессии на:

- отсутствие конкретных артефактов;
- точный состав runtime-документации;
- граф достижимости frontend-ресурсов;
- обязательные runtime-зависимости;
- запрет тяжёлых wheel-пакетов;
- состав собранного архива;
- контрольную установку, запуск страницы, repair и update.

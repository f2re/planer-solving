# Архитектура Planner Solving 2.9

## Принципы

Приложение использует явную композицию без динамического исполнения модулей, подмены методов классов и изменения уже зарегистрированных маршрутов.

Основные правила:

1. `web/backend/main.py` содержит только ASGI-точку входа.
2. `web/backend/app_factory.py` создаёт FastAPI функцией `create_app()`.
3. Пути, сеансы и репозитории принадлежат конкретному `ApplicationContext`.
4. Каждый функциональный блок возвращает независимый `APIRouter`.
5. Статический интерфейс монтируется последним.
6. Источник истины — одна SQLite-база.
7. Изменения справочников и версий выполняются транзакционно.
8. Права проверяются сервером.
9. Ожидаемые ошибки имеют стабильные коды API.
10. Внутренние исключения не раскрываются пользователю.

## Сборка приложения

```text
web.backend.main
  └─ create_app()
      ├─ ApplicationContext
      │   ├─ ApplicationPaths
      │   ├─ AnalysisSessionStore
      │   └─ TransactionalPlatformStore
      │       └─ PlatformStore
      │           └─ SQLiteWorkspaceStore
      ├─ authentication middleware
      ├─ auth router
      ├─ analysis router
      ├─ session/download router
      ├─ workspace router
      ├─ schedule router
      ├─ operations router
      ├─ system router
      └─ StaticFiles /
```

`create_app(base_dir=..., workspace_repository=...)` допускает временный каталог и тестовый репозиторий. Тесты не изменяют глобальные переменные уже созданного приложения.

## Слои

### Предметные правила

- `workspace_domain.py` — пространства, преподаватели, даты и ошибки;
- `schedule_analyzer.py` — эвристический анализ книги;
- `data_loader.py` — детерминированный разбор подтверждённой разметки;
- `template_matcher.py` — оценка полноты результата;
- `template_learning.py` — отпечатки, сходство и составные правила;
- `import_wizard.py` — предварительная нормализация и классификация импорта;
- `security.py` — пароли и непрозрачные сессионные токены.

### Хранилища

- `SQLiteWorkspaceStore` — пространства, преподаватели и основные записи шаблонов;
- `PlatformStore` — пользователи, аудит, импорт, ревизии, статистика и история;
- `TransactionalPlatformStore` — атомарное изменение шаблона вместе с ревизией;
- `AnalysisSessionStore` — временные загруженные книги и манифесты.

### HTTP

- `auth.py` — первоначальная настройка, вход, роли и middleware;
- `analysis_api.py` — потоковая загрузка и автоподбор;
- `session_api.py` — предпросмотр и скачивание;
- `workspace_api.py` — пространства и справочники;
- `workspace_schedule.py` — контрольный разбор, история и повтор запуска;
- `platform_api.py` — импорт, версии, пользователи и журнал;
- `system_api.py` — health-check и версии.

## Хранилище данных

Источник истины:

```text
data/planner-solving.sqlite3
```

Основные группы таблиц:

```text
Рабочие данные
  metadata
  workspaces
  teachers
  templates

Доступ
  users
  auth_sessions

Операции
  import_jobs
  processing_runs
  processing_files
  processing_artifacts
  audit_log

Шаблоны
  template_profiles
  template_revisions
```

SQLite работает с:

- `foreign_keys=ON`;
- WAL;
- `busy_timeout=30000`;
- короткими `BEGIN IMMEDIATE` для изменений;
- уникальными индексами;
- `PRAGMA user_version`;
- `PRAGMA quick_check` перед запуском службы.

## Транзакционные границы

Одна транзакция охватывает:

- подтверждение всего массового импорта;
- изменение шаблона и создание его ревизии;
- восстановление версии;
- завершение запуска и регистрацию артефактов;
- изменение пользователя и отзыв его сессий;
- обновление JSON-зеркал вместе с рабочим изменением.

Если запись совместимого зеркала или ревизии завершается ошибкой, изменение SQLite откатывается.

## Аутентификация и роли

Пароли хранятся как PBKDF2-HMAC-SHA256. Браузер получает случайный токен только через `HttpOnly` cookie; в базе находится SHA-256 токена.

Политика:

```text
Просмотр
  GET справочников, версий, истории и журнала

Оператор
  загрузка и разбор расписаний
  коррекция и версии шаблонов
  предварительный импорт
  повтор обработки

Администратор
  пользователи и роли
  пространства и преподаватели
  подтверждение массового импорта
  все операторские действия
```

До создания первого пользователя действует режим первоначальной настройки. После создания администратора все изменения требуют действующей сессии.

## Мастер импорта

Предварительный импорт хранится как `import_job` и не изменяет справочники. Он содержит:

- исходные строки;
- найденные заголовки и кодировку;
- сопоставление столбцов;
- статусы строк;
- рекомендуемые действия;
- пользователя и время.

Подтверждение принимает решения по строкам и применяет их одной транзакцией. Повторное подтверждение блокируется.

## Версии и обучение шаблонов

Основная запись `templates` содержит текущую разметку. `template_revisions` хранит неизменяемую историю. `template_profiles` содержит:

- составные правила листов;
- структурный отпечаток;
- текущий номер версии;
- успешные, предупредительные и неудачные применения;
- среднее качество;
- число распознанных занятий;
- время последнего использования.

Алгоритм выбора:

1. строит отпечаток новой книги;
2. отбирает применимые правила по листам;
3. запускает реальный парсер для каждого варианта;
4. оценивает полезные занятия и назначения;
5. штрафует ошибки, дубли и пустые столбцы;
6. добавляет вклад структурного сходства;
7. сохраняет статистику выбранного шаблона.

Сохранённая операторская коррекция создаёт ревизию и прикрепляет отпечаток текущей книги.

## История обработок

Каждый запуск получает UUID и фиксирует:

- пользователя и пространство;
- исходные файлы и SHA-256;
- архивную копию или жёсткую ссылку на исходник;
- группу и координаты;
- шаблон, правило и номер ревизии;
- отчёты проверки;
- итоговый статус и метрики;
- артефакты с SHA-256 и размером.

Повтор запуска создаёт новый временный сеанс из архивных исходников и использует прежние координаты. Новый результат получает отдельную запись истории.

## Журнал действий

`audit_log` хранит последовательность значимых событий. В журнал не записываются:

- пароли;
- сессионные токены;
- содержимое исходных файлов;
- traceback.

Специализированные записи содержат предметный смысл, а middleware добавляет страховочную запись успешного изменяющего HTTP-запроса.

## Сеансы анализа

`AnalysisSessionStore` отвечает за:

- UUID-сеансы;
- безопасные пути;
- атомарный `manifest.json`;
- загруженные книги и снимки преподавателей;
- очистку через 24 часа;
- защиту от выхода за каталог.

Долговременные исходники истории находятся в `data/history`, а не во временном сеансе.

## Совместимость и откат

`data/workspaces.json` и `teachers.json` — атомарные зеркала, но не источник истины. Штатный офлайн-откат восстанавливает весь согласованный каталог данных вместе с SQLite и WAL.

Более новая SQLite-схема не понижается автоматически. Приложение прекращает запуск до записи.

## Добавление API

1. Создать `build_<domain>_router(context) -> APIRouter`.
2. Передавать зависимости через контекст или протокол.
3. Использовать предметные исключения.
4. Зарегистрировать роутер до `StaticFiles`.
5. Определить роль для чтения и изменения.
6. Добавить HTTP-тест, аудит и OpenAPI-проверку.

## Добавление таблиц или полей

1. Увеличить `PLATFORM_SCHEMA_VERSION`.
2. Сделать последовательную идемпотентную миграцию.
3. Обновить `PRAGMA user_version` после успешных операций.
4. Запретить понижение более новой схемы.
5. Добавить тесты обновления, повторного запуска, повреждения и параллельной записи.
6. Проверить офлайн-обновление, резервирование и откат.

## Архитектурные запреты CI

CI проверяет отсутствие:

- `legacy_main.py`;
- `exec(compile(...))`;
- изменения `app.router.routes[:]`;
- подмены `WorkspaceStore.load`;
- старого класса `WorkspaceStore`.

Также проверяются Python, JavaScript, shell, pytest и реальная сборка автономного пакета.

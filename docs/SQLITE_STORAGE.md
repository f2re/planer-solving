# SQLite-хранилище Planner Solving 2.9

## Назначение

Основной файл данных:

```text
data/planner-solving.sqlite3
```

Он содержит не только пространства, преподавателей и шаблоны, но и операционный слой:

- пользователей и сессии;
- журнал действий;
- предварительные импорты;
- версии и статистику шаблонов;
- историю обработок;
- сведения об исходных файлах и результатах.

`data/workspaces.json` и `teachers.json` являются атомарными совместимыми зеркалами, а не источником истины.

## Версия схемы

Версия задаётся `PLATFORM_SCHEMA_VERSION` в `src/platform_store.py` и хранится в:

```sql
PRAGMA user_version;
```

Приложение:

- автоматически достраивает поддерживаемую более старую схему;
- не понижает более новую схему;
- прекращает запуск при повреждении базы;
- выполняет `PRAGMA quick_check` до запуска Uvicorn.

## Таблицы

### Рабочие данные

```text
metadata
workspaces
teachers
templates
```

### Пользователи

```text
users
auth_sessions
```

Пароль хранится как PBKDF2-HMAC-SHA256 с индивидуальной солью. В `auth_sessions` хранится только SHA-256 непрозрачного токена.

### Импорт

```text
import_jobs
```

Предварительный импорт хранит исходные строки, сопоставление столбцов, классификацию и решения. Рабочие таблицы изменяются только при подтверждении.

### Шаблоны

```text
template_profiles
template_revisions
```

`template_profiles` хранит текущие составные правила, отпечаток и статистику. `template_revisions` содержит неизменяемую историю.

### История

```text
processing_runs
processing_files
processing_artifacts
```

Исходные книги архивируются в:

```text
data/history/<run-id>/sources/
```

Если файловая система позволяет, используется жёсткая ссылка без дублирования данных. Иначе выполняется копирование.

### Аудит

```text
audit_log
```

Журнал содержит пользователя, время, действие и предметное описание. Секреты и содержимое файлов не сохраняются.

## Настройки SQLite

Для каждого соединения:

```sql
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 30000;
```

При создании базы включается WAL:

```sql
PRAGMA journal_mode = WAL;
```

Изменения выполняются короткими транзакциями:

```sql
BEGIN IMMEDIATE;
-- связанные изменения
COMMIT;
```

Это предотвращает вычисление одинаковых идентификаторов и потерю обновлений при параллельной работе.

## Транзакционные операции

Одной транзакцией выполняются:

- подтверждение массового импорта;
- изменение шаблона вместе с новой ревизией;
- восстановление версии шаблона;
- обновление пользователя и отзыв сессий;
- завершение обработки и регистрация артефактов;
- обновление совместимых JSON-зеркал.

Если один шаг завершается ошибкой, вся операция откатывается.

## Первый запуск после обновления

1. `tools.migrate` проверяет прежний `workspaces.json`.
2. `ApplicationContext` проверяет существующую SQLite-базу.
3. Если базы нет, импортируются JSON-данные или `teachers.json`.
4. Создаются таблицы операционной платформы.
5. Существующие шаблоны получают первую ревизию.
6. Формируются JSON-зеркала.
7. `tools.healthcheck` выполняет проверку.
8. Запускается Uvicorn.

Оператору не требуется ручная конвертация.

## Проверка

```bash
python -m tools.healthcheck --app-root . --data-dir data
```

Проверяются:

- версия JSON-документа;
- версия SQLite;
- наличие всех таблиц;
- `PRAGMA quick_check`;
- основное пространство;
- число пользователей;
- необходимость первоначальной настройки;
- незавершённые обработки;
- импорт приложения.

Ручная проверка:

```bash
sqlite3 data/planner-solving.sqlite3 \
  'PRAGMA quick_check; PRAGMA user_version;'
```

Утилита `sqlite3` не нужна для штатной работы.

## Резервное копирование

Нужно сохранять весь каталог:

```text
data/
```

Он включает:

- основной SQLite-файл;
- возможные `-wal` и `-shm`;
- архив исходников истории;
- совместимое JSON-зеркало;
- резервные копии миграций.

Для ручной копии работающей системы остановите службу либо используйте SQLite backup API. Нельзя копировать только основной файл при активном WAL.

## Откат

Штатный офлайн-установщик:

1. останавливает службу;
2. архивирует согласованное состояние;
3. переключает код;
4. применяет и проверяет миграцию;
5. при ошибке восстанавливает код и весь каталог данных.

Автоматическое понижение SQLite-схемы запрещено.

## Очистка истории

Текущая версия сохраняет архивные исходники до административной очистки каталога истории. При планировании политики хранения учитывайте размер загружаемых книг.

Рекомендуемая будущая политика:

- хранить последние успешные запуски за семестр;
- дольше хранить запуски с ошибками и ручными коррекциями;
- удалять архивы только вместе с соответствующими записями истории;
- предварительно создавать резервную копию.

## Многопроцессный режим

SQLite корректно сериализует несколько процессов на одном сервере. Для текущей нагрузки рекомендуется один Uvicorn worker, поскольку разбор Excel ресурсоёмок.

SQLite нельзя размещать на NFS/SMB. Для нескольких серверных узлов потребуется сетевая СУБД и общее объектное хранилище.

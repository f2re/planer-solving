# Planner Solving 2.19.1 — гарантированный запуск автономной установки

## Исправленные причины отказа

### `teachers.json.tmp: Permission denied`

Каталог вида `releases/2.19.0-ГГГГММДД-ЧЧММСС` является не временной папкой, а неизменяемым выпуском приложения. В нём находятся только код и виртуальное окружение. Постоянные данные находятся в `shared`.

Ранее `teachers.json` в выпуске был символьной ссылкой на `shared/teachers.json`, но атомарная запись строила временный путь рядом с самой ссылкой: `releases/.../teachers.json.tmp`. Пользователь службы не должен иметь права записи в выпуск, поэтому запуск закономерно завершался ошибкой.

Теперь:

- `PLANNER_SHARED_DIR` передаётся службе явно;
- `data`, `input`, `output` и `teachers.json` разрешаются до реальных путей в `shared`;
- атомарные JSON-записи используют уникальный временный файл в каталоге реальной цели;
- файл синхронизируется на диск и заменяется через `os.replace`;
- символьная ссылка выпуска сохраняется;
- выдавать службе права записи на `releases` не требуется и запрещено моделью установки.

### Ошибка `unified-operations.js` и пустая страница

Основное Vue-приложение и необязательные улучшения запуска раньше находились в одной Promise-цепочке. Исключение в runtime-модуле после успешного монтирования всё ещё переводило загрузчик в состояние фатальной ошибки.

Теперь:

- фатальным считается только невозможность загрузить или смонтировать `planner-app.js`;
- после успешного `application.mount()` интерфейс немедленно помечается рабочим;
- `unified-operations.js`, серверный черновик, клавиатурные улучшения и другие расширения запускаются изолированно;
- отказ расширения записывается в `window.__plannerSolvingBoot.optionalFailures` и консоль, но не скрывает страницу;
- сам модуль единого центра проверяет всю необходимую DOM-структуру до изменений и перехватывает ошибки наблюдателя.

## Новая обязательная приёмка

CI и проверка автономного пакета теперь подтверждают:

1. полный набор HTML, CSS, JavaScript и рекурсивных ES-module зависимостей;
2. наличие `unified-operations.js` в manifest и архиве;
3. запуск из реально установленного runtime;
4. работу при запрете записи в каталог выпуска;
5. отсутствие `teachers.json.tmp` в `releases`;
6. ответы `/`, `/assets/app.js`, `/assets/planner-app.js` и `/assets/unified-operations.js`;
7. сохранение данных после `--repair`;
8. продолжение работы страницы при исключении в необязательном runtime-модуле.

## Восстановление существующей установки

Соберите или скачайте автономный пакет версии 2.19.1 и выполните:

```bash
sudo ./install-planner-solving.sh --python bundled --strict-python --repair
sudo planner-solving-doctor --output /tmp/planner-solving-doctor.txt
sudo systemctl restart planner-solving
curl -fsS http://127.0.0.1:8001/api/health
```

Не изменяйте владельца и не выдавайте права записи каталогу `releases`. Рабочими для службы должны быть только каталоги и файлы внутри `/opt/planner-solving/shared`.

# Аудит пользовательского флоу Planner Solving

Версия аудита: 2026-08-03  
Целевая версия реализации: 2.16+  
Область: весь путь оператора — от входа и выбора пространства до выпуска, исправления и повторного формирования расписания.

## 1. Итоговый вывод

Функциональное ядро системы уже умеет работать неблокирующим образом: пригодные данные могут быть выпущены частично, календарные расхождения восстанавливаются, повреждённый файл не отменяет остальные, а занятия без преподавателя сохраняются в разделе «Не назначен».

Главная проблема теперь находится не в количестве функций, а в способе их предъявления оператору:

- исходный HTML, документация и фактическая логика описывают разные правила;
- интерфейс собран последовательными DOM-вставками поверх старого экрана;
- управление распределено между главным экраном, окном «Управление», «Центром операций» и полноэкранным редактором;
- статус файла сообщает о качестве, но не всегда отвечает на три главных вопроса: что произойдёт по умолчанию, что попадёт в результат и что оператор может изменить сейчас;
- ряд ситуаций всё ещё требует начать сеанс заново, хотя продуктовый принцип требует исправления на месте.

Целевой продукт должен восприниматься как одно рабочее место, а не как набор административных окон и технических редакторов.

## 2. Неподлежащие обсуждению продуктовые правила

1. **Результат формируется всегда**, если сервер способен создать хотя бы диагностический файл.
2. **Нет блокирующих предметных ошибок.** Есть автоматически принятые решения, предупреждения и технические отказы отдельных операций.
3. **Каждая проблема имеет решение по умолчанию.** Оператор не обязан разбираться в геометрии Excel, чтобы получить результат.
4. **Каждое решение можно изменить вручную на текущем экране.** Повторная загрузка допустима только для физически другого или повреждённого файла.
5. **Один файл не отменяет остальные.** Любой сбой локализуется по файлу, листу, диапазону, неделе или записи.
6. **Система объясняет последствия действия до его выполнения.** Не «ошибка формата», а «эта область не дала занятий; при формировании файл будет сохранён в отчёте и не повлияет на остальные».
7. **Оператор видит один основной следующий шаг.** Дополнительные действия доступны рядом, но не конкурируют с основным.
8. **Исправление файла и обучение шаблона — разные решения.** Локальная правка не должна принуждать сохранять глобальный шаблон.
9. **Состояние сеанса сохраняется.** Возврат из результата, переход между файлами и открытие служебных окон не должны терять разметку и решения.
10. **Технические подробности скрыты по умолчанию**, но доступны для диагностики администратору.

## 3. Карта текущего пути оператора

### 3.1 Вход и первоначальная настройка

Текущий путь:

1. открыть приложение;
2. создать первого администратора либо войти;
3. выбрать пространство;
4. при необходимости открыть управление справочниками.

Слабые места:

- требования к паролю исправляются отдельным runtime-модулем после построения исходной формы; исходный шаблон всё ещё содержит `required` и `minlength`;
- пользователь не понимает, чем «Управление» отличается от «Центра операций»;
- первоначальная настройка не проводит по минимально необходимым данным пространства;
- нет явной проверки готовности пространства: даты, преподаватели, шаблоны, права, каталог результатов.

Целевое решение:

- декларативная форма входа без последующих исправлений DOM;
- после первого входа — компактный мастер готовности пространства;
- один пункт «Настройки» с разделами «Пространство», «Преподаватели», «Шаблоны», «Пользователи», «Диагностика»;
- отдельный «Журнал и история» не смешивать с настройками.

### 3.2 Выбор рабочего пространства

Слабые места:

- переключатель пространства находится в верхней панели, а редактирование — в другом модальном окне;
- переключение во время активного сеанса меняет справочники и сопоставление шаблонов, но последствия недостаточно заметны;
- даты семестра воспринимаются как технические поля, хотя они участвуют в восстановлении календаря;
- реактивное обновление данных может изменить справочник во время работы без явного сообщения о версии данных.

Целевое решение:

- пространство постоянно показано рядом с названием текущего сеанса;
- при смене пространства в активном сеансе показывать: «Файлы останутся, сопоставление преподавателей и шаблонов будет пересчитано»;
- хранить снимок версии справочников, использованный при формировании;
- при внешнем изменении данных показывать ненавязчивую плашку «Данные пространства обновились» с действиями «Пересчитать» и «Оставить текущий снимок».

### 3.3 Преподаватели, шаблоны и импорт

Слабые места:

- преподаватели доступны одновременно на стартовом экране, в окне управления и в центре операций;
- мастер импорта предлагает много действий по каждой строке, но не подчёркивает рекомендуемое;
- отсутствуют быстрые массовые решения по группам одинаковых конфликтов;
- подтверждение импорта доступно только администратору, но оператору не предлагается понятный маршрут передачи решения;
- сохранение шаблона смешано с текущей корректировкой файла.

Целевое решение:

- убрать редактирование преподавателей со стартового экрана;
- оставить один каталог данных пространства;
- в импорте первым показывать итог: сколько добавится, обновится, будет пропущено и почему;
- применять безопасные решения автоматически, показывать только спорные строки;
- массовые действия: «принять рекомендуемые», «пропустить все конфликты», фильтр по статусу;
- локальная разметка хранится в сеансе независимо от решения сохранить шаблон.

### 3.4 Загрузка файлов

Сильные стороны:

- потоковая передача;
- несколько книг;
- автоматический анализ;
- разные структуры файлов.

Критические пробелы:

- после перехода к разметке нельзя добавить ещё один файл в текущий сеанс;
- нельзя заменить только один ошибочный файл;
- нельзя удалить файл из сеанса окончательно, только выключить;
- файл, который не открылся, фактически не имеет полноценного локального маршрута восстановления;
- старый `.xls` предлагается преобразовать вне системы.

Требуемая реализация:

- кнопка «Добавить файлы» на этапе проверки;
- действие «Заменить этот файл» с сохранением группы и, при возможности, разметки;
- действие «Удалить из сеанса» с отменой;
- серверные endpoints append/replace/remove для текущего сеанса;
- офлайн-конвертация `.xls` через отдельный безопасный процесс, если в пакет включён совместимый конвертер; иначе — понятный диагностический результат, а не блокировка всего запуска.

### 3.5 Автоматический подбор разметки

Слабые места:

- процент качества не объясняет, достаточно ли результата для выпуска;
- оператору показывается много метрик, но нет короткого вывода «почему выбран этот вариант»;
- выбор другого кандидата не сопровождается наглядным сравнением изменений;
- название «Автовариант» не сообщает, вернёт ли оно исходную разметку или лучший найденный шаблон.

Целевое решение:

- основной текст: «Будет использовано: шаблон X; найдено N занятий; M назначены преподавателям»;
- ссылка «Почему выбран» раскрывает 3–5 факторов;
- сравнение кандидатов показывает разницу: занятия, недели, дубли, неизвестные преподаватели;
- действия называются однозначно: «Вернуть исходный автоанализ», «Применить шаблон», «Сравнить варианты».

### 3.6 Редактор листа

Сильные стороны:

- полноэкранный режим;
- масштабирование и подгонка;
- перемещаемые панели;
- выделение строк, столбцов и диапазонов;
- автоматический пересчёт;
- сохранение положения окон по пространству.

Слабые места:

- одновременно существуют обычные числовые поля, диапазонный редактор, точный редактор и полноэкранные инструменты;
- часть интерфейса добавляется поверх другой части через DOM-манипуляции;
- нет единой модели выбора: «что сейчас выделяется» и «куда будет записано»;
- отмена не гарантированно охватывает изменения числовых полей;
- выход из редактора предлагает сохранить шаблон, хотя оператор мог исправлять только текущий файл;
- «Сохранить изменения» визуально означает шаблон, а не состояние текущего файла.

Целевое решение:

- единый контекстный инспектор справа;
- выбор режима выделения всегда виден в командной панели;
- история undo/redo для всех изменений разметки;
- автосохранение текущей разметки в сеанс;
- отдельные действия: «Применено к файлу», «Обновить шаблон», «Сохранить новым шаблоном»;
- выход без диалога, если изменения уже сохранены в сеансе;
- диалог только при изменении глобального шаблона.

### 3.7 Проверка, предупреждения и восстановление

Сильные стороны:

- предупреждения не блокируют формирование;
- автоисправления можно применить к видимой разметке;
- календарь и смена месяца редактируются без повторной загрузки;
- технические ошибки отдельного файла превращаются в локальные предупреждения.

Слабые места:

- ошибки и предупреждения остаются строками в нескольких местах;
- действие может отсутствовать или быть слишком общим;
- формулировка «файлы будут восстановлены при формировании» обещает результат, который не гарантирован;
- отсутствует единая очередь нерешённых вопросов по всем файлам;
- неизвестные преподаватели видны только как число, без списка и массового назначения.

Новый обязательный контракт проблемы:

```json
{
  "code": "stable_machine_code",
  "scope": "file|sheet|range|week|lesson|teacher|calendar|system",
  "severity": "info|attention|technical",
  "message": "Что обнаружено человеческим языком",
  "default_decision": "Что система уже сделает",
  "impact": "Что попадёт или не попадёт в результат",
  "resolved": true,
  "resolution": "auto|operator|skipped|retry",
  "actions": [
    {"type": "open_editor", "label": "Показать область", "target": {}}
  ]
}
```

Требуемая реализация:

- единая панель «Требует внимания» по всем файлам;
- каждая строка содержит принятое решение и доступное действие;
- неизвестные преподаватели — отдельная очередь сопоставления с поиском, массовым назначением и вариантом «Не назначен»;
- технический сбой — «Повторить», «Заменить файл», «Исключить», «Скачать диагностику».

### 3.8 Формирование результата

Сильные стороны:

- `allow_partial=true`;
- предварительная проверка не блокирует запрос;
- сбой одного парсера не останавливает остальные файлы;
- при нуле занятий создаётся диагностическая книга;
- исходники архивируются в истории.

Слабые места:

- перед каждым формированием выполняется последовательная проверка всех файлов, что может восприниматься как зависание;
- общий сбой экспортера или хранилища всё ещё может завершить запрос одной технической ошибкой;
- прогресс не показывает текущий файл и фазу;
- нет отмены длительного формирования;
- не различаются «проверка», «разбор», «объединение», «экспорт», «сохранение истории».

Целевое решение:

- фоновые стадии внутри одного запроса/задания с прогрессом;
- повторно использовать актуальные результаты проверки, а не проверять безусловно всё;
- при сбое основного экспортера попытаться создать диагностическую книгу и пакет отчёта;
- предоставить «Отменить» без удаления сеанса;
- хранить идемпотентный идентификатор формирования, чтобы двойной щелчок не создавал дубли.

### 3.9 Экран результата и история

До версии 2.16 экран результата фактически завершал путь: оператор мог скачать файлы или начать заново, но не вернуться к конкретному исходнику.

Первая реализация 2.16 добавляет:

- возврат к этапу проверки без потери сеанса;
- действие «Открыть и уточнить» рядом с проблемным файлом;
- явное сообщение, что текущие правки сохранены;
- единый основной термин «Сформировать результат».

Дальнейшие изменения:

- сгруппировать предупреждения по файлам и решениям;
- показывать, какие файлы реально использованы;
- добавить «Сформировать повторно после правок»;
- в истории использовать русские статусы вместо внутренних `success/warning/error`;
- повтор запуска должен открывать восстановленный сеанс перед формированием, а не сразу выполнять скрытую операцию.

## 4. Архитектурные причины UX-проблем

### 4.1 DOM-surgery вместо декларативных компонентов

Файлы `workspace-state.js`, `platform-ui.js`, `interaction-markup.js` и `editor-workspace-markup.js` ищут элементы исходного HTML и вставляют в них новые Vue-фрагменты через `querySelector`, `outerHTML` и `insertAdjacentHTML`.

Последствия:

- порядок подключения модулей становится частью бизнес-логики;
- изменение одного класса может бесшумно отключить целый раздел;
- исходный HTML остаётся устаревшим, но выглядит как источник истины;
- автоматическое тестирование проверяет наличие строк, а не реальный маршрут пользователя;
- невозможно гарантировать предсказуемый фокус, доступность и обработку ошибок.

План миграции:

1. зафиксировать текущие зоны как Vue-компоненты;
2. перенести верхнюю панель, навигацию этапов и экран результата первыми;
3. затем каталог данных и центр операций;
4. последним — редактор листа, сохранив текущее состояние и API;
5. запретить новые `insertAdjacentHTML` архитектурным тестом.

### 4.2 Несколько источников истины для текста и правил

Одни и те же правила существуют в:

- `index.html`;
- runtime-модулях интерфейса;
- README и руководствах;
- строках backend-ответов;
- тестовых контрактах.

Требуется централизованный словарь пользовательских статусов и действий. Backend возвращает структурированные коды, frontend выбирает единый текст. Документация строится из тех же понятий.

### 4.3 Смешение состояния файла, сеанса и шаблона

Нужно разделить:

- **исходник** — физический файл;
- **разметка файла** — решение только для текущего сеанса;
- **шаблон** — переиспользуемое правило пространства;
- **результат проверки** — производное состояние;
- **решение оператора** — явное переопределение автоматики;
- **снимок формирования** — неизменяемая запись в истории.

## 5. Целевая информационная архитектура

### Верхняя панель

- название продукта;
- активное пространство;
- текущий сеанс и состояние сохранения;
- «История»;
- «Настройки»;
- пользователь.

### Основной маршрут

1. **Файлы** — добавить, заменить, удалить, задать группу.
2. **Проверка** — сводная готовность и список вопросов.
3. **Редактор** — появляется только для выбранного вопроса или по явному запросу.
4. **Результат** — скачать, вернуться к вопросу, сформировать повторно.

Этапы не должны скрывать данные. Это навигация по состоянию одного сеанса, а не последовательный мастер с потерей контекста.

### Боковая панель файла

- включён/исключён;
- группа;
- выбранный лист и шаблон;
- число занятий;
- число назначенных преподавателей;
- принятое календарное решение;
- вопросы, требующие внимания;
- действия «Открыть», «Заменить», «Удалить».

## 6. Визуальные и интерактивные правила в стиле macOS

Под «стилем macOS» понимаются не копирование интерфейса Apple и не декоративная имитация, а следующие качества:

- спокойная иерархия без конкурирующих акцентов;
- одна основная кнопка в контексте;
- компактные сегментированные переключатели;
- системная типографика и чёткие размеры;
- панели с умеренным blur только там, где он помогает отделить слой;
- предсказуемые диалоги с безопасным действием по умолчанию;
- управление мышью, клавиатурой и тачпадом;
- сохранение положения, масштаба и состояния окон;
- немедленная обратная связь и возможность отмены;
- раскрытие сложности по требованию, а не сразу.

Обязательные сочетания:

- `Ctrl/Cmd + O` — добавить файлы;
- `Ctrl/Cmd + Enter` — сформировать результат;
- `Ctrl/Cmd + Z` / `Shift + Ctrl/Cmd + Z` — отмена/повтор разметки;
- `Esc` — закрыть верхний диалог;
- стрелки и Shift — работа с диапазонами таблицы;
- `Ctrl/Cmd + S` — сохранить шаблон только при явном режиме редактирования шаблона.

## 7. План реализации

### P0 — оператор всегда достигает результата

1. Единая сводка готовности сеанса.
2. Возврат из результата к конкретному файлу — выполнено в первой серии 2.16.
3. Append/replace/remove файлов в активном сеансе.
4. Структурированный контракт проблем и действий.

## 9. Матрица обязательных ситуаций

| Ситуация | Решение по умолчанию | Действия оператора | Результат |
|---|---|---|---|
| Последовательная смена месяца | принять календарный переход | изменить месяц/дату недели | обычный выпуск |
| Противоречие подписи месяца и точной даты | приоритет точной даты | выбрать источник календаря | выпуск с пояснением |
| Не найден преподаватель | «Не назначен» | сопоставить одному или массово | занятие не теряется |
| Не найдено занятий | сохранить исходник и диагностику | открыть редактор, заменить или исключить | диагностическая книга |
| Один файл повреждён | пропустить только его | повторить, заменить, исключить | остальные выпускаются |
| Не найден лист | выбрать лучший доступный лист | выбрать лист вручную | файл остаётся в сеансе |
| Ошибка координат | безопасная нормализация | показать и изменить область | выпуск по исправленной разметке |
| Сбой предварительной проверки | попробовать при формировании | повторить проверку | формирование доступно |
| Сбой экспортера | создать диагностический fallback | повторить экспорт, скачать пакет | скачиваемый отчёт |
| Смена пространства | сохранить файлы, пересчитать справочники | оставить снимок или применить новое | контролируемое изменение |
| Истёк сеанс | восстановить сохранённый черновик | загрузить отсутствующий исходник | не начинать всё заново |

# Центр операций Planner Solving 2.9

## Назначение

Центр операций объединяет действия, которые раньше требовали прямой работы с файлами или не имели истории:

- безопасный массовый импорт;
- версии и составные правила шаблонов;
- история обработок и сформированных файлов;
- локальные пользователи и роли;
- журнал действий;
- статистика качества и автоматическое обучение шаблонов.

Центр открывается кнопкой **«Центр операций»** в верхней панели. Все данные относятся к активному рабочему пространству.

## Первый запуск и вход

Если пользователей ещё нет, приложение показывает форму первоначальной настройки. Необходимо создать первого администратора:

- логин;
- отображаемое имя;
- пароль не короче 10 символов.

До завершения первоначальной настройки сервер работает в локальном установочном режиме. После создания администратора все изменения требуют входа.

Пароли хранятся только в виде PBKDF2-HMAC-SHA256 с индивидуальной солью. Сессия передаётся через `HttpOnly` cookie, не доступную JavaScript.

## Роли

### Администратор

Может:

- создавать и изменять пользователей;
- подтверждать массовый импорт;
- изменять преподавателей;
- создавать и удалять пространства;
- выполнять все операторские действия;
- просматривать журнал.

### Оператор

Может:

- загружать и разбирать расписания;
- корректировать разметку;
- создавать версии шаблонов;
- создавать предварительный импорт;
- просматривать историю и журнал.

Не может подтверждать массовый импорт преподавателей или управлять пользователями.

### Просмотр

Может просматривать:

- пространства и справочники;
- версии шаблонов;
- историю обработок;
- сформированные файлы;
- журнал действий.

Изменения блокируются сервером, а не только интерфейсом.

## Мастер импорта

### 1. Выбор типа и файла

Поддерживаются:

- преподаватели: CSV, TSV, TXT, JSON;
- шаблоны: JSON либо табличный файл с JSON-разметкой в столбце.

Система определяет:

- кодировку UTF-8, Windows-1251 или CP866;
- разделитель `;`, `,`, табуляцию или `|`;
- строку заголовков среди первых 20 строк;
- стандартные и русскоязычные названия столбцов.

На этом этапе рабочие данные не изменяются.

### 2. Сопоставление столбцов

Для преподавателей оператор сопоставляет исходные столбцы с полями:

- краткое имя;
- полное ФИО;
- должность;
- звание;
- учёная степень.

После каждого изменения система пересчитывает предпросмотр.

### 3. Проверка строк

Каждая строка получает статус:

- **Новая** — будет добавлена;
- **Изменение** — найден преподаватель или шаблон с отличающимися полями;
- **Совпадение** — запись уже существует без изменений;
- **Конфликт** — повтор внутри файла либо неоднозначное соответствие;
- **Ошибка** — обязательные данные не распознаны.

Для каждой строки можно выбрать действие:

- добавить;
- объединить заполненные поля;
- заменить;
- пропустить.

Отчёт до применения можно скачать в CSV.

### 4. Подтверждение

Только администратор может применить импорт. Все выбранные действия выполняются одной SQLite-транзакцией. При любой критической ошибке изменения откатываются целиком.

Повторно применить один и тот же предварительный импорт нельзя.

## Версии шаблонов

Каждое сохранение шаблона создаёт новую неизменяемую ревизию с:

- номером версии;
- автором;
- временем;
- комментарием;
- основной разметкой;
- составными правилами;
- структурным отпечатком книги.

В интерфейсе показываются изменившиеся координаты. Любую прежнюю версию можно восстановить. Восстановление не удаляет историю: оно создаёт следующую ревизию с содержимым выбранной версии.

## Составные шаблоны

Один шаблон может содержать несколько правил для разных листов книги. Каждое правило включает:

- название;
- шаблон имени листа или регулярное выражение;
- собственный объект разметки.

Пример:

```text
Основная разметка       → любой основной лист
Правило «Заочная форма» → имя листа содержит «заоч»
Правило «Магистратура»  → имя листа соответствует «магистр|магистратура»
```

При загрузке книги система проверяет все применимые правила реальным парсером и оставляет наиболее качественный вариант.

## Автоматическое обучение

После автоматического анализа строится структурный отпечаток книги. Он учитывает:

- количество и названия листов;
- размер таблицы;
- шаг и ширину недельного блока;
- число строк в учебном дне;
- число пар;
- способ размещения занятия;
- наличие нижнего блока преподавателей;
- диагностические признаки.

При ранжировании учитываются одновременно:

1. результат реального парсера;
2. полнота назначений преподавателей;
3. количество уникальных занятий;
4. ошибки и предупреждения;
5. структурное сходство с ранее подтверждёнными книгами;
6. накопленная статистика качества шаблона.

Когда оператор сохраняет исправленную разметку, текущий отпечаток прикрепляется к новой версии шаблона. Так последующие похожие книги получают более точный автоподбор без непрозрачного машинного обучения.

## История обработок

Каждое формирование расписания создаёт запись запуска. Сохраняются:

- пространство;
- пользователь;
- время начала и завершения;
- статус;
- число исходных файлов;
- SHA-256 каждого файла;
- группа;
- применённый шаблон и его версия;
- координаты разметки;
- отчёты проверки;
- количество занятий, предупреждений и ошибок;
- итоговые файлы с размером и SHA-256.

Сформированные файлы можно повторно скачать из истории, пока они находятся в каталоге `output`.

## Журнал действий

Журнал фиксирует:

- вход и выход;
- создание и изменение пользователей;
- изменение пространств;
- добавление, изменение и удаление преподавателей;
- создание, изменение, восстановление и удаление шаблонов;
- предварительный и подтверждённый импорт;
- завершение обработки;
- успешные изменяющие HTTP-запросы.

Запись содержит пользователя, время, действие, сущность и краткое описание. Пароли, токены и содержимое исходных файлов в журнал не записываются.

## Резервирование

Новые таблицы находятся в том же файле:

```text
data/planner-solving.sqlite3
```

Штатный офлайн-установщик резервирует весь каталог данных после остановки службы. Это сохраняет:

- пользователей;
- роли и сессии;
- импорт;
- версии шаблонов;
- историю обработок;
- журнал действий;
- основное содержимое пространств.

Для ручного резервирования работающей системы нельзя копировать только основной SQLite-файл без активного WAL. Остановите службу либо используйте SQLite backup API.

## Диагностика

```bash
python -m tools.healthcheck --app-root . --data-dir data
```

Проверка подтверждает:

- версию операционной схемы;
- наличие всех таблиц;
- `PRAGMA quick_check`;
- основное пространство;
- число пользователей и необходимость первоначальной настройки;
- число незавершённых обработок;
- совместимое JSON-зеркало.

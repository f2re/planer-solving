# Planner Solving 2.21 — назначения преподавателей и чистый интерфейс

## Что было неверно

Предыдущий диалог назначения открывался только для дисциплин без найденного преподавателя и позволял выбрать одного человека на всю дисциплину. Это не соответствовало реальной модели кафедры: лектор, преподаватель практики и резерв могут быть разными.

Стартовый экран одновременно показывал заголовок, длинное описание, три рекламных тезиса, подпись изображения, большую область загрузки и дополнительное пояснение формата. На невысоком экране нижняя часть карточки выходила из естественной компоновки.

Итоговая иллюстрация существовала в автономном пакете, но добавлялась только при первоначальном запуске JavaScript. В этот момент итоговый экран ещё не был создан директивой `v-if`, поэтому изображение не попадало в DOM.

## Реализованная модель

### Правила преподавателей

Для каждой дисциплины оператор при необходимости задаёт:

- преподавателя лекций;
- преподавателя практических занятий;
- резервного преподавателя.

Пустое значение сохраняет автоматический режим. Настройки являются предпочтениями, а не способом скрыть конфликт: общий граф назначения по-прежнему проверяет временные коллизии и может использовать резерв.

Правила передаются через совместимый контейнер `period_overrides.teacher_overrides` с внутренними ключами `@lecturer`, `@other` и `@reserve`. Старые клиенты и сохранённые сеансы продолжают работать.

### Сохранение

Правила текущего сеанса автоматически входят в серверный черновик вместе с остальными `period_overrides`.

При включённом параметре «Использовать эти правила в следующих расписаниях» правила сохраняются в отдельной таблице рабочего пространства. При следующей загрузке файлов они применяются автоматически до формирования.

### Интерфейс

На основном экране остаются три действия:

1. добавить файлы;
2. настроить преподавателей;
3. сформировать результат.

Диалог назначений содержит поиск и три компактных поля на дисциплину. Технические термины и длинные объяснения удалены. Точные координаты и служебные операции остаются в контекстных разделах.

Стартовая карточка получила устойчивую двухколоночную компоновку и отдельный режим для невысоких экранов. Повторяющиеся тезисы и подпись иллюстрации удалены.

Итоговая иллюстрация теперь подключается наблюдателем DOM после фактического появления `result-card`, поэтому работает при каждом формировании и после восстановления серверного черновика.

## Совместимость и проверка

- данные правил хранятся локально в SQLite;
- внешние изображения и CDN не используются;
- существующие ручные назначения остаются совместимыми;
- автономная сборка включает новые Python-, JavaScript- и CSS-файлы;
- регрессии покрывают API правил, канонизацию ФИО, роли, реактивную итоговую иллюстрацию и адаптивную компоновку.

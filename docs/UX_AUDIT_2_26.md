# UX-аудит 2.26 — загрузка, проверка, результат

Дата: 2026-08-11

Аудит выполнен по принципам профиля `.gemini/agents/frontend-developer.md`: один основной следующий шаг, progressive disclosure, предсказуемая навигация и отсутствие конкурирующих CTA.

## Найденные дефекты

### 1. Первый экран — прогресс загрузки выходил за карточку

`upload-stream-progress` имел ширину `min(440px, 78vw)`. На десктопе левая колонка стартовой карточки могла быть существенно уже `78vw`, поэтому индикатор рассчитывался относительно viewport, а не родительской области.

Решение 2.26: `width: 100%`, `max-width: 440px`, `min-width: 0`; контейнер загрузки также явно ограничен шириной dropzone. Длинная подпись прогресса переносится внутри блока.

### 2. Экран проверки — два главных действия «Сформировать»

После UX-надстроек кнопка формирования была одновременно в верхней панели готовности и в нижней sticky-панели. Два одинаково сильных CTA нарушали последовательность работы.

Решение 2.26: главным остаётся только «Сформировать» в панели готовности. Внизу остаются вторичные действия «Перепроверить файлы» и «Очистить сеанс».

### 3. Экран результата — до шести конкурирующих действий

Исходный HTML содержал скачивание общего результата, недельного результата и новый сеанс. `operator-flow.js` добавлял «К исправлениям», а `editor-workspace-markup.js` добавлял вторую кнопку возврата и историю формирования. В результате навигация, скачивание и служебные действия находились в одной куче.

Решение 2.26:

1. `← К исправлениям` — отдельная навигация сверху слева;
2. `Скачать расписание` — единственное основное действие;
3. `Скачать недельное` — вторичное действие;
4. `История формирования` и `Новые файлы` — третичные служебные действия;
5. старые дублирующие кнопки возврата сохраняются невидимыми только как Vue-event trigger для обратной совместимости и не участвуют в интерфейсе.

### 4. Изображения — тестировалась сигнатура, а не декодируемость

CI считал WebP корректным, если присутствовали `RIFF` и `WEBP`. Это не гарантировало, что браузер сможет полностью декодировать файл.

Решение 2.26: UI-изображения переведены в PNG. Тест проверяет структуру PNG, CRC chunks, `IHDR/IDAT/IEND` и реальную распаковку IDAT через `zlib`. WebP удалён из обязательного runtime.

## Целевой флоу

**1. Добавить файлы → 2. Проверить только то, что требует внимания → 3. Сформировать → 4. Скачать результат.**

Исправления и история остаются доступными, но не конкурируют с основным действием текущего этапа.

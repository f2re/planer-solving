# 📅 Планировщик Расписания (OR-Tools)

Система автоматизированного формирования сводного расписания преподавателей из групповых расписаний в формате Excel.

## 🌟 Основные возможности
- **Автоматическая трансформация:** Преобразование расписаний учебных групп в персональные графики преподавателей.
- **Управление преподавателями:** Веб-интерфейс для редактирования списка преподавателей, их должностей и званий.
- **Интеллектуальный парсинг:** Распознавание сложных структур Excel (объединенные ячейки, многострочные блоки).
- **Стилизация по образцу:** Генерация выходных файлов, полностью соответствующих заданному шаблону оформления.
- **Offline Mode:** Полная работоспособность без доступа к интернету (все библиотеки локализованы).

## 🛠 Технологический стек
- **Backend:** Python 3.11+, FastAPI, openpyxl, pandas.
- **Frontend:** Vue.js 3, Bootstrap 5, Axios (все зависимости в `web/frontend/assets/`).
- **Data:** JSON-ориентированное хранение конфигурации преподавателей.

## 🚀 Быстрый запуск

### Установка зависимостей
```bash
pip install -r requirements.txt
pip install fastapi uvicorn python-multipart
```

### Запуск веб-интерфейса
Используйте готовый скрипт запуска:
```bash
./start_web.sh
```
После запуска интерфейс будет доступен по адресу: `http://localhost:8000`

### Использование CLI (командная строка)
Для быстрой генерации из файла-примера:
```bash
python3 main.py
```
Результат сохранится в `output/result.xlsx`.

## 🌐 Развертывание как сервис (Systemd)
Для работы в фоновом режиме на Linux (Ubuntu/Debian):

1. Скопируйте пример сервиса (отредактируйте пути внутри, если нужно):
   ```bash
   sudo cp planner-web.service /etc/systemd/system/
   ```
2. Перезагрузите демона и запустите сервис:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable planner-web
   sudo systemctl start planner-web
   ```
3. Проверка статуса:
   ```bash
   sudo systemctl status planner-web
   ```

## 📂 Сценарии использования (Use Cases)

### 1. Формирование сводного расписания семестра
- Откройте веб-интерфейс.
- Загрузите Excel-файл группового расписания (например, `522.xlsx`).
- Система проанализирует все недели, пары и дисциплины.
- Нажмите "Скачать результат" для получения файла, где по строкам распределены преподаватели, а по столбцам — даты и пары.

### 2. Управление штатом кафедры
- В правой панели интерфейса можно добавлять новых преподавателей.
- Изменяйте их краткие и полные имена (краткое имя используется для поиска в файлах групп).
- Указывайте должности и ученые степени для корректного отображения в шапке отчета.

### 3. Автономная работа (Offline Deployment)
- Проект полностью упакован для работы во внутренней сети без выхода в интернет.
- Все JS/CSS библиотеки находятся в `web/frontend/assets/`.
- Достаточно установить Python-пакеты один раз, и система будет работать вечно.

## 🏗 Структура проекта
- `src/` — ядро системы (парсинг, трансформация, экспорт).
- `web/` — веб-слой (FastAPI backend и Vue.js frontend).
- `obrazec/` — эталонные файлы и примеры.
- `output/` — директория для сгенерированных отчетов.
- `teachers.json` — база данных преподавателей.

## 🧠 Умное распределение нагрузки
В системе реализован интеллектуальный алгоритм распределения занятий между несколькими преподавателями:
- **Равномерное деление (Round-Robin):** Если для одного вида занятий (например, лекций) указано несколько преподавателей, нагрузка между ними распределяется поровну.
- **Контроль пересечений:** Система автоматически отслеживает занятость каждого преподавателя. Если выбранный преподаватель уже занят в текущий слот на другой дисциплине, система автоматически назначит следующего доступного из списка.
- **Поддержка потоковых лекций:** Если один и тот же преподаватель ведет одну и ту же дисциплину у разных групп в одно и то же время, система распознает это как совмещенное занятие и не считает это конфликтом.

## 🌍 Развертывание в Production

### 1. Запуск Backend (Uvicorn / Gunicorn)

**Базовый вариант (один процесс):**
```bash
uvicorn web.backend.main:app \
    --host 127.0.0.1 \
    --port 8000 \
    --proxy-headers \
    --forwarded-allow-ips '*'
```

**Production вариант с Gunicorn (несколько воркеров):**
```bash
gunicorn web.backend.main:app \
    --workers 4 \
    --worker-class uvicorn.workers.UvicornWorker \
    --bind 127.0.0.1:8000 \
    --proxy-protocol \
    --forwarded-allow-ips '*' \
    --access-logfile - \
    --error-logfile -
```

### 2. Настройка Nginx
Конфигурационный файл находится в `deploy/nginx.conf`.

**Основные шаги:**
1. Создать симлинк на конфигурацию:
   ```bash
   sudo ln -s /home/user/planner-solving/deploy/nginx.conf /etc/nginx/sites-available/fastapi
   sudo ln -s /etc/nginx/sites-available/fastapi /etc/nginx/sites-enabled/
   ```
2. Удалить дефолтную конфигурацию (опционально):
   ```bash
   sudo rm /etc/nginx/sites-enabled/default
   ```
3. Проверить конфигурацию на ошибки:
   ```bash
   sudo nginx -t
   ```
4. Перезагрузить Nginx:
   ```bash
   sudo systemctl reload nginx
   # Или перезапустить
   sudo systemctl restart nginx
   ```
5. Включить автозапуск:
   ```bash
   sudo systemctl enable nginx
   ```

# 📅 Planner Solving

Интерактивная система разбора разнородных расписаний Excel и формирования сводного расписания преподавателей. Она рассчитана на книги с разными строками начала, столбцами недель, размерами дневных блоков, объединёнными ячейками, несколькими листами и отличающимся оформлением.

Система не обрабатывает файл вслепую и не требует от оператора заранее переделывать Excel. Сначала выполняется анализ структуры и проверка сохранённых шаблонов реальным парсером. Затем оператор видит исходный лист, при необходимости исправляет разметку, даты или преподавателей на месте и формирует результат. Сомнения парсера показываются как неблокирующие подсказки; пригодные данные не отбрасываются.

Текущая версия указана в [`VERSION`](VERSION). Версии совместимого JSON-документа и SQLite-схемы проверяются отдельно.

## Основные возможности

### Разбор и восстановление расписаний

- автоматический поиск строки недель и диапазона недельных столбцов;
- определение строки месяцев, сетки занятий и нижнего блока преподавателей;
- поддержка объединённых ячеек;
- поддержка построчной и многострочной записи занятия;
- отдельная разметка каждого файла;
- HTML-предпросмотр исходного листа;
- выделение, растягивание и перемещение диапазонов;
- автоматическое исправление очевидных ошибок координат;
- последовательная смена месяца внутри недели без ложной ошибки;
- ручная правка месяца и даты каждого дня без повторной загрузки;
- неблокирующие предупреждения вместо отказа от формирования;
- частичная обработка: один проблемный файл не отменяет остальные;
- сохранение занятий без преподавателя в разделе **«Не назначен»**;
- диагностический Excel, если занятия пока не извлечены;
- аварийный плоский экспорт при ошибке сложного оформления;
- общее и недельное расписание;
- потоковая загрузка без фиксированного ограничения приложения по размеру или количеству файлов.

### Черновик операторской работы

После загрузки сервер автоматически сохраняет:

- исходные файлы;
- включение и отключение файлов;
- названия групп;
- текущую разметку;
- ручные даты и месяцы;
- способ выбора календаря;
- выбранный файл и этап работы;
- готовый результат и список коррекций.

После `F5`, закрытия вкладки или перезапуска веб-приложения незавершённый сеанс восстанавливается автоматически. Формирование не закрывает редактор: из результата можно вернуться к конкретному файлу и исправить его. Повреждённую книгу можно заменить отдельно, не теряя остальные файлы и правки.

Подробности: [`docs/SESSION_DRAFT_RECOVERY.md`](docs/SESSION_DRAFT_RECOVERY.md).

### Автоподбор и обучение шаблонов

- проверка автоматической разметки и всех шаблонов реальным парсером;
- ранжирование по числу уникальных занятий, найденных преподавателей, недель, дисциплин, дублей и замечаний;
- структурный отпечаток книги;
- оценка сходства с ранее подтверждёнными форматами;
- статистика успешности и среднего качества шаблона;
- автоматическое обучение после сохранения операторской коррекции;
- составные шаблоны с отдельными правилами для разных листов книги.

### Центр операций

Кнопка **«Центр операций»** открывает единый адаптивный интерфейс:

- обзор состояния пространства;
- мастер предварительного импорта;
- историю обработок и сформированных файлов;
- версии шаблонов и откат;
- редактор составных правил листов;
- управление пользователями и ролями;
- журнал действий.

Полное руководство: [`docs/OPERATIONS_CENTER.md`](docs/OPERATIONS_CENTER.md).

## Рабочие пространства

Каждое пространство изолирует:

- преподавателей;
- шаблоны;
- даты семестра;
- историю обработок;
- предварительные импорты;
- журнал действий;
- параметры формирования результата.

Источник истины — транзакционная база:

```text
data/planner-solving.sqlite3
```

При первом запуске существующий `data/workspaces.json` автоматически импортируется в SQLite. `workspaces.json` и `teachers.json` продолжают атомарно обновляться как совместимые зеркала для старых CLI-сценариев и безопасного отката.

Подробности: [`docs/SQLITE_STORAGE.md`](docs/SQLITE_STORAGE.md).

## Безопасный мастер импорта

Прямой массовый импорт справочников отключён. Любой импорт проходит четыре этапа:

1. выбор CSV, TSV, TXT или JSON;
2. определение кодировки, разделителя и строки заголовков;
3. ручное сопоставление столбцов и предпросмотр;
4. подтверждение выбранных изменений администратором.

Каждая строка получает статус:

- новая;
- изменение;
- совпадение;
- конфликт;
- ошибка.

Оператор выбирает действие: добавить, объединить, заменить или пропустить. До подтверждения рабочие данные не изменяются. Подтверждённый импорт выполняется одной SQLite-транзакцией. Отчёт можно скачать в CSV.

## Версии шаблонов

Каждое сохранение создаёт неизменяемую ревизию с:

- номером версии;
- автором;
- временем;
- комментарием;
- основной разметкой;
- составными правилами;
- структурным отпечатком книги.

В Центре операций видны изменившиеся координаты. Восстановление прежней версии не удаляет историю, а создаёт следующую ревизию с выбранным содержимым.

## История обработок

Каждый запуск формирования сохраняет:

- пользователя и пространство;
- время и статус;
- SHA-256 исходных файлов;
- группы и применённые координаты;
- ручные календарные решения;
- выбранный шаблон, правило и номер версии;
- отчёты проверки;
- число занятий и предупреждений;
- итоговые файлы, размеры и SHA-256.

История доступна внутри рабочего пространства. Результаты можно повторно скачать, пока соответствующие файлы находятся в `output`.

## Пользователи и роли

При первом запуске приложение предлагает создать первого администратора. После этого изменения требуют входа.

Роли:

- **Администратор** — пользователи, пространства, преподаватели, подтверждение импорта и все операторские функции;
- **Оператор** — разбор расписаний, коррекция, шаблоны, предварительный импорт и история;
- **Просмотр** — чтение данных, истории, версий и журнала.

Пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной солью. Сессии передаются через `HttpOnly` cookie. Права проверяются сервером.

## Журнал действий

Журнал фиксирует пользователя, время и краткое описание значимых операций:

- вход и выход;
- изменение пользователей;
- создание и изменение пространств;
- операции с преподавателями;
- создание, обновление, восстановление и удаление шаблонов;
- предварительный и подтверждённый импорт;
- завершение обработки.

Пароли, токены и содержимое загруженных файлов в журнал не записываются.

## Рабочий процесс оператора

1. Войти и выбрать пространство.
2. Проверить преподавателей, шаблоны и даты семестра.
3. При массовом обновлении использовать **Центр операций → Импорт**.
4. Загрузить расписания `.xlsx` или `.xlsm`.
5. Дождаться анализа и автоподбора шаблонов.
6. Просмотреть автоматические исправления и найденные занятия.
7. При необходимости исправить диапазоны, даты или преподавателей прямо на текущем экране.
8. Оставить автоматический календарь либо выбрать приоритет Excel или пространства.
9. Сохранить подтверждённую разметку новой версией шаблона.
10. Сформировать расписание; предупреждения не блокируют результат.
11. При необходимости вернуться из результата к проблемному файлу и повторить формирование.
12. Просмотреть запуск и результаты в **Центр операций → История**.

## Архитектура

Backend создаётся фабрикой `create_app()` без динамического `exec`, monkey patch и изменения уже зарегистрированных маршрутов.

```text

  └─ create_app()
      ├─ ApplicationContext
      │   ├─ AnalysisSessionStore
      │   └─ PlatformStore
      │       └─ SQLiteWorkspaceStore

      ├─ analysis router
      ├─ session router
      ├─ workspace router
      ├─ schedule router
      ├─ operations router
      ├─ system router
```

## Запуск из исходного кода

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
bash start_web.sh
```

Перед запуском `start_web.sh`:

1. проверяет прежний JSON-документ;
2. создаёт или обновляет SQLite-схему;
3. импортирует существующие данные;
4. выполняет `PRAGMA quick_check`;
5. проверяет таблицы операционной платформы;
6. запускает Uvicorn только после успешного health-check.

Интерфейс: `http://localhost:8001`.

## Автономная установка и обновление

На машине с Интернетом и подходящим Python:

```bash
bash offline/build_offline_bundle.sh \
  --output dist \
  --python "$(command -v python3)"

cd dist
sha256sum -c *.tar.gz.sha256
```

В `dist` создаются:

```text
planner-solving-offline-*-runtime.tar.gz
planner-solving-offline-*-runtime.tar.gz.sha256
install-planner-solving.sh
README-INSTALL.txt
```

На автономный сервер копируются все четыре файла. Установка или обновление:

```bash
chmod +x install-planner-solving.sh
sudo ./install-planner-solving.sh \
  --python bundled \
  --strict-python
```

Восстановление существующей установки с пересозданием выпуска и venv:

```bash
sudo ./install-planner-solving.sh \
  --python bundled \
  --strict-python \
  --repair
```

По умолчанию приложение устанавливается в:

```text
/opt/planner-solving
```

Постоянные данные находятся в `/opt/planner-solving/shared`. Установщик использует встроенный управляемый CPython, отдельный venv каждого выпуска, резервную копию данных, проверку импортов, миграции, health-check и автоматический откат.

Подробности:

- [`docs/INSTALLATION.md`](docs/INSTALLATION.md);
- [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md);
- [`docs/OFFLINE_UPDATE.md`](docs/OFFLINE_UPDATE.md).

## Диагностика

Для установленной системы:

```bash
sudo planner-solving-python
sudo planner-solving-doctor
sudo systemctl status planner-solving --no-pager -l
sudo journalctl -u planner-solving -n 120 --no-pager
curl -fsS http://127.0.0.1:8001/api/health
```

Для запуска из исходников:

```bash
python -m tools.healthcheck --app-root . --data-dir data
```

Health-check проверяет:

- импорт приложения;
- JSON-зеркало;
- `PRAGMA quick_check`;
- версию SQLite-схемы;
- наличие таблиц операционной платформы;
- основное пространство;
- число пользователей и необходимость первоначальной настройки;
- доступность обязательных каталогов и библиотек.

## Поддерживаемые исходные данные

Поддерживаются `.xlsx` и `.xlsm`. Старый `.xls` необходимо один раз сохранить как `.xlsx`. Книги, где расписание представлено изображением, объектами рисования или зашифровано без доступных значений ячеек, невозможно разобрать как таблицу. Такой файл можно заменить отдельно, не удаляя остальные книги текущего сеанса.

## Надёжность

- короткие SQLite-транзакции;
- WAL, внешние ключи и `busy_timeout`;
- уникальные индексы;
- атомарные JSON-зеркала и манифесты сеансов;
- серверный черновик операторских правок;
- атомарная замена одного исходного файла после предварительной проверки;
- отказ от открытия более новой схемы;
- серверная проверка ролей;
- безопасные пароли и HttpOnly-сессии;
- защита путей сеансов и скачивания;
- внутренние исключения не раскрываются пользователю;
- активные временные сеансы хранятся 24 часа с продлением при восстановлении;
- автономный пакет содержит SHA-256 каждого файла;
- внешние службы и сетевые шрифты не используются.

# 📅 Planner Solving

Инструмент для разбора групповых расписаний Excel и формирования сводного расписания преподавателей. Система рассчитана на книги с различными строками начала, столбцами недель, размерами дневных блоков, объединёнными ячейками и разным оформлением.

Файл не обрабатывается вслепую: сначала выполняется автоматический анализ, затем система проверяет на книге все сохранённые шаблоны пространства и выбирает вариант с наибольшим количеством достоверно распознанных данных. Оператор видит будущую область парсинга в HTML-таблице, при необходимости исправляет её мышью, пальцем или клавиатурой и запускает контрольный разбор.

Текущая версия приложения хранится в [`VERSION`](VERSION). Версии совместимого документа и SQLite-хранилища проверяются отдельно.

## Пространства и хранение

Данные разделены на независимые рабочие пространства. Пространство удобно использовать для отдельной кафедры, факультета, филиала, семестра или проекта.

В каждом пространстве хранятся:

- собственный список преподавателей;
- название, описание и цвет интерфейса;
- серверные шаблоны разметки Excel;
- даты начала и окончания семестра;
- настройки формирования итогового расписания.

Источник истины — транзакционная база `data/planner-solving.sqlite3`. При первом запуске существующий `data/workspaces.json` автоматически импортируется в SQLite. Если его нет, основное пространство создаётся из `teachers.json`.

`data/workspaces.json` и `teachers.json` продолжают атомарно обновляться как совместимые зеркала для старых CLI-сценариев, экспорта и безопасного отката. Новый backend не читает рабочее состояние из этих зеркал.

Новые пространства получают актуальный диапазон ближайшего учебного семестра без жёстко заданного года. Сервер проверяет формат дат и запрещает начало позже окончания.

### Импорт и экспорт

- пространство целиком: переносимый JSON-пакет с преподавателями, шаблонами и настройками;
- преподаватели: CSV с разделителем `;` или JSON;
- шаблоны разметки: JSON;
- импорт можно выполнить с добавлением записей либо с полной заменой текущего набора;
- дубликаты по нормализованному ФИО или названию шаблона пропускаются и отражаются в отчёте.

Подробные руководства: [`docs/WORKSPACES.md`](docs/WORKSPACES.md) и [`docs/SQLITE_STORAGE.md`](docs/SQLITE_STORAGE.md).

## Что умеет система

- автоматически искать строку учебных недель и диапазон недельных столбцов;
- определять строку месяцев, начало и конец сетки занятий;
- оценивать число пар, шаг строк и размер блока учебного дня;
- находить нижний блок дисциплин, лекторов и других преподавателей;
- учитывать объединённые ячейки без изменения исходной книги;
- разбирать отдельные строки «код / дисциплина / аудитория» и многострочное занятие в одной ячейке;
- брать преподавателя из нижнего блока, из самой сетки или из обоих источников;
- проверять каждый серверный шаблон реальным парсером и выбирать наиболее информативный;
- показывать качество подбора, замечания, найденные занятия и неназначенные дисциплины;
- корректировать диапазоны щелчком, растягиванием и перетаскиванием прямо в HTML-предпросмотре;
- сохранять и редактировать шаблоны на сервере внутри пространства;
- потоково принимать любое количество файлов без фиксированного ограничения приложения по размеру;
- формировать общее и недельное расписание;
- работать автономно, без внешних сетевых ресурсов.

## Рабочий процесс оператора

1. Выбрать пространство в верхней панели.
2. При необходимости открыть **Управление** и проверить преподавателей, шаблоны и даты семестра.
3. Загрузить файлы `.xlsx` или `.xlsm`.
4. Дождаться автоматического анализа и проверки всех шаблонов пространства.
5. Для каждого файла проверить предложенную разметку и показатели распознавания.
6. При необходимости выбрать назначение диапазона и провести по ячейкам таблицы: сетка, недели, месяцы, блок дисциплин или отдельный столбец.
7. Нажать **«Проверить разметку файла»** и устранить оставшиеся замечания.
8. Сохранить исправленную разметку как новый шаблон либо обновить существующий.
9. Проверить все включённые файлы и сформировать расписание.

Руководство по разметке: [`docs/OPERATOR_GUIDE.md`](docs/OPERATOR_GUIDE.md). Автоподбор и интерактивная коррекция: [`docs/TEMPLATE_MATCHING.md`](docs/TEMPLATE_MATCHING.md). Архитектура: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Архитектура backend

Приложение создаётся фабрикой `create_app()` без `exec`, monkey patch и ручного изменения списка маршрутов. Все пути, сеансы и репозитории принадлежат конкретному `ApplicationContext`; функциональные области оформлены независимыми `APIRouter`.

```text
web.backend.main
  └─ create_app()
      ├─ ApplicationContext
      │   ├─ AnalysisSessionStore
      │   └─ SQLiteWorkspaceStore
      ├─ analysis/session/workspace/schedule/system routers
      └─ StaticFiles /
```

Ожидаемые прикладные ошибки переводятся в единообразные ответы API. Текст непредвиденного внутреннего исключения пользователю не возвращается и остаётся только в журнале сервера.

Полное описание: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Обычный запуск из исходного кода

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
bash start_web.sh
```

Перед запуском `start_web.sh`:

1. проверяет и мигрирует прежний JSON-документ;
2. создаёт либо открывает SQLite;
3. импортирует прежние данные при первом запуске;
4. выполняет `PRAGMA quick_check` и проверку версий;
5. запускает Uvicorn только после успешного health-check.

Интерфейс: `http://localhost:8001`.

## Офлайн-установка и обновление

Для закрытого контура предусмотрен самостоятельный пакет, содержащий код, Python-колёса, контрольные суммы, миграции, установщик и откат.

### Сборка на машине с интернетом

```bash
bash offline/build_offline_bundle.sh --output dist
cd dist
sha256sum -c *.tar.gz.sha256
```

### Первая установка или обновление

```bash
tar -xzf planner-solving-offline-*.tar.gz
cd planner-solving-offline-*
python3 verify_bundle.py .

sudo bash install_or_update.sh \
  --install-dir /opt/planner-solving \
  --service-user planner \
  --port 8001
```

Для переноса данных из прежней установки добавляется:

```bash
--legacy-dir /путь/к/старому/planer-solving
```

Установщик:

- проверяет совместимость Python и архитектуры;
- устанавливает зависимости без доступа к интернету;
- создаёт новый выпуск рядом со старым;
- останавливает службу перед резервированием SQLite и WAL;
- резервирует общие данные;
- применяет миграции и проверяет SQLite;
- атомарно переключает текущую версию;
- проверяет `/api/health`;
- автоматически откатывает код и согласованную копию данных при ошибке.

Ручной откат:

```bash
sudo bash rollback.sh --install-dir /opt/planner-solving --port 8001
```

Полное руководство: [`docs/OFFLINE_UPDATE.md`](docs/OFFLINE_UPDATE.md). Разработка миграций: [`docs/MIGRATIONS.md`](docs/MIGRATIONS.md).

## Системные проверки

```bash
curl http://127.0.0.1:8001/api/health
curl http://127.0.0.1:8001/api/system/version
```

Ответ содержит версию приложения, версию совместимого документа, версию SQLite-схемы и тип активного хранилища.

Локальная проверка:

```bash
python -m tools.healthcheck --app-root . --data-dir data
```

Проверка прежней JSON-миграции без записи:

```bash
python -m tools.migrate --check --json
```

## Тестирование

```bash
pytest -q tests
```

Проверки охватывают:

- анализ Excel и полный операторский API-сценарий;
- ранжирование шаблонов по полезным данным;
- потоковую запись загрузок без фиксированного лимита приложения;
- фабрику приложения и уникальность маршрутов;
- отсутствие динамического `exec`, monkey patch и route surgery;
- автоматический импорт JSON в SQLite;
- транзакционную параллельную запись без потерянных обновлений;
- уникальные ограничения преподавателей и шаблонов;
- запрет понижения более новой JSON- или SQLite-схемы;
- SQLite `quick_check` и системный health-check;
- сборку и контроль целостности офлайн-пакета.

## Структура

```text
src/
  schedule_analyzer.py        # поиск структуры и предпросмотр Excel
  data_loader.py              # разбор по подтверждённой разметке
  template_matcher.py         # проверка и ранжирование шаблонов
  workspace_domain.py         # правила и ошибки предметной области
  sqlite_workspace_store.py   # единственный рабочий репозиторий
  workspace_store.py          # малый совместимый экспорт доменных имён
  data_migrations.py          # миграция прежнего JSON-документа
  transformer.py              # преобразование занятий
  exporter.py                 # итоговый Excel
  weekly_exporter.py          # недельный вариант
web/backend/
  main.py                     # ASGI-точка входа
  app_factory.py              # фабрика FastAPI
  app_context.py              # пути, сеансы и зависимости
  errors.py                   # единые обработчики ошибок
  analysis_api.py             # загрузка, анализ и подбор шаблонов
  session_api.py              # предпросмотр, сеансы и скачивание
  workspace_api.py            # пространства, преподаватели и шаблоны
  workspace_schedule.py       # проверка и формирование результата
  system_api.py               # health-check и версии
web/frontend/                 # автономный интерфейс Vue
tools/                        # миграции и диагностика
offline/                      # автономная сборка, установка и откат
data/planner-solving.sqlite3  # рабочая база, создаётся автоматически
data/workspaces.json          # совместимое зеркало, создаётся автоматически
input/analysis_sessions/      # временные загруженные книги
output/                       # сформированные файлы
```

## Поддерживаемые исходные данные

Поддерживаются `.xlsx` и `.xlsm`. Старый `.xls` необходимо открыть в Excel или LibreOffice и сохранить как `.xlsx`. Книги, где расписание представлено изображением, объектами рисования или защищёнными листами без доступных значений ячеек, требуют предварительного преобразования.

## Безопасность и надёжность

- изменения рабочих данных выполняются короткими SQLite-транзакциями;
- включены внешние ключи, WAL, тайм-аут ожидания записи и уникальные индексы;
- совместимые JSON-зеркала записываются атомарно;
- приложение отказывается открывать данные более новой версии;
- нельзя удалить последнее пространство;
- даты семестра валидируются сервером;
- исходные имена загрузок очищаются;
- расписания записываются на диск блоками по 1 МБ и не считываются целиком в оперативную память;
- фактический предел загрузки задают диск, файловая система и обратный прокси;
- временные сеансы удаляются через 24 часа;
- пути сеансов и скачивания проверяются;
- внутренние исключения не раскрываются пользователю;
- офлайн-пакет содержит SHA-256 каждого файла;
- рабочие данные не включаются в пакет обновления;
- внешние службы и сетевые шрифты не используются.
